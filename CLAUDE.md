# Cellar — project guide for Claude Code

iPhone wine-cellar app: scan a bottle label (or type it), keep a cellar
database, total each wine's and the whole cellar's estimated value, find where
to buy (online offers + nearby stores with directions), tasting notes, wishlist,
export, and drink-window reminders.

**Native SwiftUI + SwiftData, iPhone-only, iOS 18+, zero third-party Swift
dependencies.** Project files are generated by XcodeGen from `project.yml`.

> Builds and tests pass (Xcode 26, iOS 18.6 simulator, 2026-09-13): unit tests
> plus the `CellarUITests` click-through.

## Build / run / test

```bash
# from the repo root (project.yml is here):
brew install xcodegen           # once
xcodegen generate               # regenerate after ANY file add/remove/rename
open Cellar.xcodeproj

# build/test from CLI:
xcodebuild -project Cellar.xcodeproj -scheme Cellar \
  -destination 'platform=iOS Simulator,name=iPhone 16' build
xcodebuild -project Cellar.xcodeproj -scheme Cellar \
  -destination 'platform=iOS Simulator,name=iPhone 16' test
```

- **Re-run `xcodegen generate` whenever files are added, removed, or renamed.**
  Editing an existing file's contents does not need it. ("Cannot find type X in
  scope" almost always means a new file isn't in the target yet — regenerate.)
- Needs an **iOS 18 simulator** installed. Set your Team ID in `project.yml`
  (`DEVELOPMENT_TEAM`) and a unique bundle id if `com.doony.cellar` is taken.

## Conventions (do not break these)

- **Hand-maintained `Cellar/Info.plist` and `Cellar/Cellar.entitlements`** are
  referenced via build settings (`INFOPLIST_FILE`, `CODE_SIGN_ENTITLEMENTS`).
  Do **not** use XcodeGen's `info:`/`entitlements:` keys — they regenerate/empty
  those files. They're excluded from the source scan in `project.yml` (via
  `excludes:`) so they aren't double-copied into the bundle ("Multiple commands
  produce Info.plist").
- iPhone-only: `TARGETED_DEVICE_FAMILY: "1"` lives at the target level.
- On-device only: SwiftData store + `NSFileProtectionComplete`. No analytics, no
  third-party SDKs. Nothing leaves the phone except an export the user initiates
  or the wine identity sent to price it.
- Toggle view visibility with `el.hidden`-style SwiftUI state, keep code matching
  the surrounding style.

## Architecture

```
Cellar/                      app source (Swift)
├── CellarApp.swift          @main; SwiftData ModelContainer (schema list here)
├── Info.plist               camera/photo/location usage keys; NSAllowsLocalNetworking
├── Cellar.entitlements      data protection
├── Models/
│   ├── Wine.swift           Wine (identity + rating 1–5 + communityScore + isWishlist
│   │                        + lwin7 + imageURL), Bottle, ValuationSnapshot,
│   │                        PurchaseOption, enums (WineType has .tint)
│   └── TastingNote.swift     dated note + optional 1–5 score
├── Scan/                    VisionKit DataScanner live OCR (+ capturePhoto for the
│                            label image), Vision still-photo fallback, LabelParser (pure)
├── LWIN/                    free Liv-ex identity matching: LWINDatabase (loads
│                            Resources/LWIN.csv if present else lwin_sample.csv,
│                            inverted token index), LWINMatcher (scoring), LWINRecord
├── Valuation/              ValuationService/PurchaseService protocols; Manual + Remote
│                            clients; ValuationConfig (endpoint in UserDefaults, API key
│                            in Keychain); ValuationCoordinator (7-day cache, persists
│                            snapshots + offers); CellarStats (pure aggregation)
├── Purchase/               MerchantOffer, NearbyStores (MapKit + one-shot location)
├── Export/                 CSV + PDF exporters
├── Notifications/          DrinkWindowNotifier (local notifications)
├── Resources/lwin_sample.csv   20-wine sample (illustrative codes; replace with real)
└── Views/                  RootTabView (Cellar/Wishlist/Value tabs), CellarListView,
                            WineDetailView, AddWineFlow, WishlistView, WhereToBuyView,
                            CellarDashboardView (Swift Charts + export menu),
                            SettingsView (endpoint+key), LWINMatchView, ScanSheet,
                            ShareSheet, RatingAndThumbnail (StarRating/StarsInline/WineThumbnail)
CellarTests/                unit tests (LabelParser + real Vision OCR, CellarStats, LWIN, valuation, export)
CellarUITests/              XCUITest click-through of all tabs (pricing test skips without a local proxy)
scripts/import_lwin.py      converts the Liv-ex LWIN download (CSV/XLSX) into Resources/LWIN.csv
proxy/                      Node 18+ pricing proxy for the user's Oracle host
```

### Key design decisions
- **Offline-first.** The app is fully usable with no network: manual valuation,
  LWIN matching (bundled sample), MapKit nearby stores. Online pricing is an
  optional layer behind `ValuationService`/`PurchaseService`.
- **Provider-agnostic pricing endpoint.** The app calls one JSON contract
  (`GET {baseURL}/valuation?lwin=&q=&vintage=&currency=`); the `proxy/` adapts
  Wine-Searcher / Apify / a mock into it. See `proxy/README.md`.
- **Secrets:** provider key lives on the proxy (or, for direct use, in the app's
  Keychain via `APIKeyStore`) — never in the bundle/Info.plist/logs. HTTPS is
  required except for localhost/`*.local`/private LAN IPs (dev proxy), matched
  by `NSAllowsLocalNetworking` in Info.plist.
- **LWIN:** `Wine.lwin7` (7-digit wine identity) + `lwin11` (with vintage). The
  bundled `lwin_sample.csv` codes start at 9000001 and are **illustrative, not
  authoritative** — replace with the free Liv-ex LWIN database:
  `python3 scripts/import_lwin.py <download.xlsx|csv>` writes
  `Cellar/Resources/LWIN.csv` (then `xcodegen generate`; the loader prefers it).
  CC BY 4.0 — keep the Liv-ex credit in `LWINMatchView`. The repo bundles a
  converted copy (~205k wines and spirits; mixed cases skipped;
  `--exclude-spirits` for wine only). Matching indexes producer title + producer + wine; the
  Add form auto-snaps only via `LWINMatcher.confidentPick`.

## Known unverified / gotchas
- The bundled LWIN.csv (~205k wines and spirits, 26 MB) loads in ~1.5 s at ~175 MB peak on a
  Mac (expect slower on a phone). It loads in the background at launch; matching
  returns nothing until it finishes.
- Scanned-photo capture works on a **real device**, not the simulator camera —
  use the photo-picker fallback in the simulator.
- Adding a new SwiftData model or field is a lightweight migration; if an
  existing store errors on launch, delete the app from the simulator once.
- The Wine-Searcher response schema isn't public — the `ADJUST` block in
  `proxy/server.js` maps best-effort field names; verify with `DEBUG_UPSTREAM=1`
  against a real key.
